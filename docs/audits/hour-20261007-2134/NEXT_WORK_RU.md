# Следующая работа по общей причине

Это порядок продолжения, а не обещание окончания за фиксированное число часов. Исходные критерии готовности и все 32 строки сохранены в plan-32-status.json.

1. Разобрать повторяющийся BUFFERING_TIMEOUT при обратном переключении качества и при запуске неподтверждённых cached leaves. Для каждого повторения сохранить точный request scope, preparation/generation, этап reload, выбранную ветку и Media3 error/HTTP category без URL и credentials. Отделить неработающую временную ссылку/сегмент от ошибки выбора или восстановления. Исправить общий контракт, затем повторить затронутые сценарии на новой установленной APK. Текущая проверка 480→240 не закрыта; requested voice/quality и позиция сохранились, active source отсутствовал.
2. Завершить хранение SourceTruth по request profile и связь с logical variant. Не переносить decoder proof на другую дорожку, файл или профиль. Проверить одновременно несколько представлений одного URI и ротацию только одного logical variant. В текущих 500 карточках 10 332 native leaves не показали несколько профилей одного URI; это не проверка gated adapters и не доказательство соответствия реальным дорожкам.
3. Закрыть общую транспортную матрицу единым набором сценариев: точный фильм/год/S/E, голоса, качество/Auto, реальные audio/video indexes, субтитры, обновление ссылки и позиция, torrent-файл/seek/отмена, download/offline/resume. Один изолированный direct offline/seek прошёл, полная матрица ещё нет. Live search HDRezka на двух карточках вернул HTTP 500; недоступные references не заменять fixture и не включать gates без декодирования.
4. Продолжать сохранённый Android journal без переклассификации ошибки в отсутствие вариантов. Отдельно учитывать текущий SHA и старые APK. Timeout/ошибка discovery/player/harness остаются unresolved. Повторить затронутые ошибки после исправления; 500 checked cards, 500 resolved cards и полноценная transport matrix — разные факты. S/T по 1000 сохраняют значение inventory/enrichment snapshots; это не 2000 decoder launches. Каждый действительно новый coverage cohort должен исключать все сохранённые предыдущие IDs.
5. После функционального соответствия удалить заменённые активные legacy wrappers. Измерить контролируемые холодный/повторный старт, CPU/RAM, очереди и отмену. Выполнить финальную сборку/установку/SHA/проверку данных/backend/crash/ANR, опубликовать checkpoint, ограничения и откат. Пассивные /proc samples текущего часа не заменяют controlled benchmark; общий старт ≤5 секунд не подтверждён.

Ускорение достигается общей реализацией и единым проверочным набором для каждого транспорта, а не удалением вариантов, уменьшением выборок или засчитыванием компиляции как успешного воспроизведения.
