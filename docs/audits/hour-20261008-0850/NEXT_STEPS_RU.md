# Следующие работы Movia

План 32 блоков остаётся картой критериев. Для ускорения повторные сборки и установки объединяются после взаимосвязанных исправлений; независимые read-only наблюдения идут во время одного decoder audit. Оценка готовности остаётся по проверкам.

| Очередь | Общая причина / результат | Блоки |
|---|---|---|
| 1 | Сохранять точную доказанную article reference в native leaf; reload выбранного источника через ProviderContract без повторного поиска, сохраняя movie/year/S/E/voice/ID. Не угадывать URL из hash. Проверить ошибки поиска, rotation, segment recovery, bounded cancellation. | 3–7, 9, 19 |
| 2 | Отдельное SourceTruth evidence по request profile, tracks и DRM; доказать audio/quality происхождение для parallel same-URI representations и renderer event attribution. | 5, 8, 10–11, 19 |
| 3 | Завершить сохранённые 500 названий, повторить затронутые ошибки на конечном SHA; сохранить два независимых 1000-ID cohort audit с корректной оценкой доступности. | 24–30 |
| 4 | Один общий live набор для каждого доступного direct/torrent транспорта: точная серия/file, голос/audio index/subtitles, качество/Auto, seek/resume/stop/cancel, download/offline. | 9–12, 19–20, 29 |
| 5 | Проверить реальную доступность Zona/Collaps/Filmix/Octopus/Kinoplay/VideoCDN/Alloha; включать только доказанные адаптеры, удалить wrappers после parity. Новый adapter при реальном reference требует дополнительных блоков. | 13–18, 22 |
| 6 | CPU/RAM/queues/cancellation и cold/warm ≤5s; полный tests/build/install/SHA/crash/ANR/backend proof, финальный checkpoint/docs/rollback. | 21, 23, 30–32 |

Текущая APK исправляет привязку DataSource к MediaSource, atomic resume, decoder-frame watchdog и stale recovery/selection. Exact 240→480→240 matrix пока не прошла; basic direct download/offline/seek прошёл. Новые mass outcomes учитываются отдельно от старых APK. Недоступность статьи/провайдера не выводится из timeout или HTTP ошибки поиска.
