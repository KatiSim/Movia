# Movia: граница доказательств воспроизведения

Изменения этого прохода исправляют общий обмен данными между нативным каталогом и Media3. В коде нет условий по названию фильма или catalog ID. Идентификаторы конкретных фильмов встречаются только в сценариях живой проверки.

## Причина

В каталоге могли сохраниться нативные варианты без sourceId: быстрый cached GET намеренно не выполняет discovery и запись в SourceTruth. Android раньше пропускал сообщение о первом кадре такого варианта. Поздняя публикация неизвестного качества могла затем стереть измеренное значение. Отдельно индекс сопоставлял доказательства по provider/URL, без полного профиля запроса: новые заголовки или индексы дорожек могли унаследовать старое качество и ошибки.

## Исправленный контракт

| Граница | Поведение | Реализация |
|---|---|---|
| Первый кадр Media3 | Фактическая высота немедленно обновляет текущий fixed leaf, сохраняя его stream ID. Adaptive-контейнер сохраняет Auto и остальные представления. | withLocalDecodedMeasurement, PlaybackSession |
| Повторная публикация | Измерение сохраняется для того же URL, заголовков, userAgent, транспорта, DRM, дорожек, файла и S/E. Обновлённый профиль не получает доказательство прежнего. | preserveMeasurementScope, DomainPlaybackResolver |
| Cached native feedback | Нативный leaf без sourceId может передать измерение через собственный authenticated endpoint. Отпечатки вычисляются из реально подготовленного leaf до delayed discovery. | nativeFeedbackScope, native_variant_feedback |
| Проверка адресата | Endpoint сам находит карточку и точный вариант; проверяет media ID, тип, S/E, stream ID, locatorHash и profileHash. URL от вызывающего кода не принимается. | /internal/playback-availability/native-variant-success |
| SourceTruth overlay | Доказательства применяются только к совпадающим provider, URL и профилю запроса. Старые мигрированные строки без profile hash не подтверждают свежий профиль. | streamer, playback_availability_index |
| Ошибка после изменения профиля | Android передаёт оба отпечатка. Backend проверяет их перед записью и в самом SQL UPDATE, включая гонку между SELECT и UPDATE. | media3-failure, source_playback_evidence |
| HLS dimensions | Высота и ширина сегмента могут быть доказаны без полной duration. Длительность сегмента не становится длительностью фильма или серии. | media_content_probe |

Cached GET остаётся read-only. Источник регистрируется при discovery либо при принятом подтверждении первого кадра. Положительное доказательство декодирования и доступность после последующей сетевой ошибки остаются разными фактами. Названия студий и заявленные провайдером качества не становятся доказанными дорожками или размерами.

## Проверка

Kotlin и Python имеют общие golden fingerprints, включая Unicode и заголовки. Backend-регрессии проверяют другую карточку/вариант, другую серию, изменение URL/headers, отсутствие sourceId, миграцию профиля, ошибку старого профиля и interleaved discovery между чтением и записью. Живые результаты и SHA конкретной установленной APK находятся в final-installed-proof.json, offline_smoke.json и hour-summary.json. Первые неудачные итерации сохранены отдельно; они не заменяются утверждением общего PASS.

## Незавершённые общие причины

- `recordNativeFailure` пока требует sourceId. Cached native leaf без этого ID передаёт успешный кадр через новый endpoint, но не может сохранить отрицательный результат до индексации. Следующий шаг — общий scoped native feedback для ошибок без ID; нельзя объявлять отсутствие записи об ошибке здоровьем источника.

- `_resolve_clean_provider_registry` возвращает только outcome.streams. Статус ProviderDiscoveryOutcome теряется на границе общего resolver; дальше ряд исключений превращается в пустые списки. Терминальный UNAVAILABLE в инвентаризации не доказывает, что исключены внутренние ошибки. Нужен общий структурированный результат через resolver/queue, включая поздние ветки.
- Автоматический recovery budget в PlaybackSession зависит от размера candidates. Нужен отдельный предел попыток/времени операции при сохранении всех найденных вариантов.
- Часть direct MP4 остаётся с неизвестными размерами, если ограниченный head sample не содержит необходимой metadata. Успех HTTP range не заменяет реальный запуск. Нужна общая проверка контейнера/потока и разбор Media3 stall.
- Legacy-compatible balancer и transport wrappers ещё присутствуют. Их удаление требует проверки оставшихся вызовов и функционального соответствия.
- Гейты неподтверждённых Zona/Collaps/Filmix/Octopus и остальных провайдеров не включались. Нужны актуальные живые references и playback; fixtures не подтверждают доступность.

Эти пункты остаются в плане. Новый checkpoint подтверждает текущий объём исправлений, а не завершение всего проекта.

Уточнение схемы fingerprint: backend/Kotlin digest содержит headers, userAgent, transport, DRM license URL, audio/video indexes, file index/path. Android local merge дополнительно сравнивает drmScheme и S/E. Для будущих DRM-адаптеров требуется включить drmScheme в общий versioned fingerprint и живую матрицу; текущий проход не объявляет проверку DRM.
